# オーダリングソフト雛形 練習用システム (Ordering Practice System)

医療現場における**オーダリングシステム（オーダー発行側・部門受信側）**のデータ連携の仕組みを理解・練習するための雛形実装です。  
`incident-system` の隣（`/home/a/Desktop/ai/ordering`）に構築されています。

---

## 📐 システム構成

```text
/home/a/Desktop/ai/ordering/
├── package.json              # 依存関係定義 (Express, EJS)
├── start.js                  # 送信側・受信側の両方を同時起動するランチャー (HTTP/HTTPS両対応)
├── certs/                    # 🔒 SSL/TLS 暗号化通信用証明書 (server.key, server.crt, openssl.cnf)
├── scripts/
│   └── generate-certs.js     # SSL自己署名証明書自動生成スクリプト (SAN対応)
├── shared/
│   └── orderSchema.js        # 共通データ定義（オーダー種別、優先度、患者プリセット）
├── sender/                   # 🚀 送信側（医師・病棟・外来のオーダー発行システム）
│   ├── server.js             # ポート 4000 (HTTPS/HTTP)
│   ├── sent_orders_db.json   # 送信履歴データ
│   └── views/index.ejs       # オーダー入力・発行Web画面
└── receiver/                 # 🏥 受信側（各部門システム: 薬剤部、放射線科、検査室、栄養科等）
    ├── server.js             # ポート 5000 (HTTPS/HTTP)
    ├── orders_db.json        # 受信オーダーデータ
    └── views/index.ejs       # 部門別オーダー監視・実施確認Webモニター
```

## 🚀 起動方法

### 一括起動（デフォルト: HTTPS 暗号化モード）
送信側（Port 4000）と受信側（Port 5000）の両方が1コマンドで **HTTPS 暗号化通信** で起動します：

```bash
cd /home/a/Desktop/ai/ordering
npm start
# または npm run start:https
```

### HTTP (平文通信) で起動したい場合
```bash
npm run start:http
```

### 個別起動
```bash
# 送信側のみ起動 (Port 4000)
npm run sender          # HTTPS
npm run sender:http     # HTTP

# 受信側のみ起動 (Port 5000)
npm run receiver        # HTTPS
npm run receiver:http   # HTTP
```

### SSL/TLS 自己署名証明書の再生成
```bash
npm run gen-certs
```
※マシンのLAN内IPアドレスを自動検出し、`localhost` や LAN IP（`192.168.x.x` 等）を Subject Alternative Name (SAN) に組み込んだ証明書を生成します。

| :--- | :--- | :--- | :--- |

> **「詳細設定」→「localhostにアクセスする（安全ではありません）」** をクリックして進めてください。

## 📝 練習シナリオ

### シナリオ1: 処方オーダー送信と双方向リアルタイム・ステータス更新
1. ブラウザで [`https://localhost:4000`](https://localhost:4000)（送信側）と [`https://localhost:5000`](https://localhost:5000)（受信側）を左右に並べて開きます。
2. **送信側（Port 4000）**で「💊 処方」タブを選択し、患者を選んで **[🚀 受信サーバーへオーダーを送信]** をクリックします。
   - 送信側の履歴カードには初期ステータス `📥 受信済`（または `📤 送信済`）と表示されます。
3. **受信側（Port 5000）**の画面に瞬時にオーダーカードが届きます。
4. 受信側で **[受付]** ボタンを押します。
   - 受信側から送信元へ **自動コールバック通知（Webhook）** が送信されます。
   - **送信側（Port 4000）の画面が自動で `🟡 受付済 (処方鑑査OK、調剤準備中)` にリアルタイム更新されます！**
5. 受信側で **[✅ 完了]** ボタンを押します。
   - **送信側（Port 4000）の画面が即座に `✅ 完了 (調剤・ピッキング完了、病棟出庫済)` に切り替わります！**
   - 医師・病棟側はブラウザを手動リロードすることなく、部門側の進捗（受付済・完了）を画面上でリアルタイムに把握できます。

### シナリオ2: 各種オーダーの送信練習
- **💉 点滴・注射オーダー**: 輸液名、投与速度（ml/h）、投与経路（末梢/CV）の指定。
- **🩻 放射線科検査オーダー**: 胸部X線、CT、MRIのモダリティ指定、撮影室/病室ポータブルの指定。
- **🔬 検体検査オーダー**: 生化学、血算、採血検体の指定。
- **🍱 食事選択オーダー**: 常食、全粥、減塩食、アレルギーの指定。

### シナリオ3: 既存カルテ (`incident-system`) との連携
送信側（Port 4000）の送信先URL欄を `http://localhost:3000` に切り替えることで、既存の電子カルテシステム（Port 3000）に対して点滴・放射線・食事オーダーを直接送信するテストも行えます。

## 💊 薬品集マスタ・薬剤データベース連動機能

院内採用薬マスタ（`/home/a/Desktop/ai/薬品集マスタ.xlsx`）から抽出・生成された薬剤データベースを搭載しています。

```text
/home/a/Desktop/ai/ordering/
├── shared/
│   ├── medicines.json        # 薬品集マスタ JSON (全607品目の詳細データ)
│   ├── medicines.db          # 薬品集マスタ SQLite (FTS5全文検索インデックス付)
│   └── medicineMaster.js     # 薬剤検索・サジェスト・正規化モジュール
└── scripts/
    └── import-medicines.py   # Excelからルビ除外・正規化してDB/JSONを再生成するスクリプト
```

### データベース概要
- **総件数**: 全607品目
  - 💊 **内服薬**: 344品目
  - 💉 **注射剤**: 147品目
  - 🧴 **外用薬**: 116品目
- **主な管理項目**:
  - 薬品ID（`DR0001`等）、薬品名・規格、一般名（有効成分）、カナ、薬効分類（大分類・中分類）
  - 先発/後発、採用区分、標準用法・用量
  - **調剤・投与適応**: **粉砕可否（〇/△/×）**、**簡易懸濁可否（〇/×）**、**脱カプセル可否**
  - **調剤上の注意事項**（例: `【調剤注意】苦味ありのため条件付き粉砕可` 等）

### オーダリング画面での連動
1. **送信側（Port 4000）**:
   - **リアルタイム・インクリメンタルサーチ**: 薬品名・カナ・一般名・IDで入力サジェスト。
   - **標準用法・用量の自動補完**: 薬品選択時に標準用法用量が自動入力。
   - **調剤適応カード表示**: 選択薬の粉砕可否、簡易懸濁、調剤注意アラートを即時表示。
   - **薬品集マスタ検索モーダル**: 607品目を区分別に絞り込み・検索してワンクリック選択。
   - **自由記載欄**: 医師からの特記事項・患者希望・注意事項を入力可能。
2. **受信側（Port 5000）**:
   - **横1行テーブル表示**: 1件1行で視認性の高いコンパクト表示。
   - **調剤注意・粉砕適応バッジ**: `粉砕:〇` `粉砕:△` `懸濁:〇` `⚠️調剤注意` を一覧にインライン表示。
   - **マウスホバーで全文ツールチップ**: 指示内容と薬品マスタ詳細（一般名、薬効、粉砕適応、調剤注意）を表示。
   - **詳細モーダル**: オーダー情報・薬品マスタカード・自由記載欄・実施履歴・生JSONを美しく整理して表示し、ワンクリックで「受付済」「実施完了」に更新可能。

### マスタ再インポートコマンド
```bash
npm run import-medicines
```

## 🔌 API仕様（抜粋）

### 1. 総合オーダー受信 API
- **URL**: `POST http://localhost:5000/api/orders/receive`
- **Content-Type**: `application/json`
- **リクエストボディ**:
  ```json
  {
    "orderType": "PRESCRIPTION",
    "priority": "STAT",
    "patient": { "id": "P001", "name": "山田 太郎", "department": "一般病棟" },
    "doctor": { "name": "北島 先生", "department": "内科" },
    "details": {
      "medicine": "ジスロマック錠250ｍｇ",
      "medicineId": "DR0007",
      "dosage": "1日1回500mg3日間",
      "days": 3,
      "prescriptionType": "臨時",
      "remarks": "嚥下困難のため粉砕調剤の検討をお願いします"
    }
  }
  ```
- **レスポンス**:
  ```json
  {
    "success": true,
    "message": "オーダーを正常に受信しました",
    "orderId": "PRE-20260915-1234",
    "status": "RECEIVED"
  }
  ```

### 2. 薬剤マスタ検索 API
- **URL**: `GET /api/medicines?q={キーワード}&category={内服薬|注射剤|外用薬}&limit=50`
- **レスポンス**: 該当する薬剤リスト（粉砕可否・調剤注意含む）
